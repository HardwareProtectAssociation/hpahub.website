# 硬件数据库数据模型

硬件数据按“分类定义—测试项目定义—硬件记录—专栏文章”组织。迁移 `1760000037` 增加文章集合；`1760000038` 为字段补充输入类型、单位、必填、选项、帮助文字，并为硬件增加公开状态和封面；`1760000039` 为硬件记录增加提交成员关系。迁移不清理或重写既有硬件记录。

| 集合 | 用途 | 关键数据 |
| --- | --- | --- |
| `hw_types` | 硬件分类，如 CPU、显卡、主板、耳机、鼠标、显示器 | `key`、`label`、显示名称字段、排序 |
| `hw_fields` | 每个分类的动态基础参数字段 | 分类、分组、字段 key、显示名、类型、单位、必填、选项、帮助文字、顺序 |
| `hw_tables` | 每个分类的可重复测试表格及列定义 | 分类、表 key、标题、JSON 列定义、顺序 |
| `hardware` | 单个硬件产品及实测报告 | 分类 key、名称、品牌、副标题、提交成员、公开状态、JSON `data` |
| `hardware_media` | 硬件关联媒体路径（现有集合） | 硬件关系、JSON 路径 |
| `hardware_options` | 动态下拉选项（现有集合） | 分类、选项值、顺序 |
| `hardware_articles` | 产品的图文专栏文章 | 硬件关系、作者、标题、摘要、JSON 正文、图片、发布状态 |

`hw_fields` 和 `hw_tables` 是分类级配置：管理员新增“分辨率”字段或测试表列后，之后该分类的硬件表单与报告即可填写它；CPU 无需设置显示器专属字段。`hardware.data` 保存按照这些配置填写的标量参数和测试结果，既有测试数据不迁移改写。表格列的 JSON 定义沿用各分类的列配置，不要求各类硬件共享同一套指标。


专栏文章与结构化报告分开保存。文章正文使用 JSON，允许后续实现段落、标题、图片等内容块；`images` 保存上传图片，`hardware_id` 将文章关联到单件硬件。一个硬件可以有多篇文章，发布状态与文章内容独立于报告数据。

所有集合默认仅超级管理员可通过 PocketBase 直接读写。Go 服务允许所有成员新增并公开发布硬件报告和图文文章；成员可编辑自己提交的报告，管理员可管理全部报告并配置分类、字段和测试表格。登录成员可浏览自己的未公开报告，其他访客只能看到已公开报告和文章。硬件封面字段已预留但录入界面尚未上传封面；文章图片可上传。删除硬件时文章随硬件级联删除。
